# Dataset

## Intended dataset: OULAD

The model is designed and written against the **Open University Learning Analytics
Dataset (OULAD)**.

| | |
|---|---|
| Source | https://analyse.kmi.open.ac.uk/open-dataset |
| Mirror | UCI ML Repository, dataset 349 |
| Licence | CC BY 4.0 (attribution required, commercial use permitted) |
| Scale | ~32,600 students, 7 modules, 22 module presentations, 10M+ VLE interaction rows |
| Anonymisation | Already anonymised by the publisher using k-anonymity and l-diversity |
| Citation | Kuzilek, J., Hlosta, M., Zdrahal, Z. (2017). *Open University Learning Analytics dataset.* Scientific Data 4, 170171. |

### Tables used

| File | One row is | Used for |
|---|---|---|
| `courses.csv` | a module presentation | resolving the checkpoint day from `module_presentation_length` |
| `studentInfo.csv` | a student's enrolment in a presentation | demographics + the `final_result` label |
| `studentRegistration.csv` | a registration event | registration timing; `date_unregistration` is **excluded** (leaks the outcome) |
| `assessments.csv` | an assessment in a presentation | assessment due dates, used to decide which assessments existed before the checkpoint |
| `studentAssessment.csv` | a submitted assessment | early scores and submission timeliness |
| `studentVle.csv` | one student-day-resource click record | all engagement features |

### To use the real data

1. Download the CSV bundle from the source link above.
2. Unzip the seven CSVs into `data/raw/` using the exact filenames listed in
   `config/config.yaml` under `data.tables`.
3. Run `make train`. Nothing else changes — the pipeline is written against this
   schema and does not care where the CSVs came from.

## What is actually in `data/raw/` in this repository

**A synthetic dataset generated by `src/data/generate_synthetic_oulad.py`.**

This project was developed in a sandboxed environment whose network policy could
not reach `analyse.kmi.open.ac.uk`, UCI, or Kaggle. Rather than ship an untested
pipeline, the generator produces data with the **identical schema, column names
and category vocabularies** as OULAD (including quirks like the `55<=` age band
and February/October `B`/`J` presentation codes), so every stage of the pipeline
runs and is tested end to end.

The generator is not noise. Each student is given a latent ability/engagement
term that drives, in a chain: how often they interact with the VLE → whether and
how promptly they submit early assessments → what they score → and finally their
`final_result`. This produces a genuine, learnable early signal with a realistic
amount of irreducible noise, which is what makes the reported metrics meaningful
as a demonstration that the pipeline works.

**Generated scale:** 2,240 student-enrolments, 4 modules × 4 presentations,
~1.0M VLE interaction rows, 6,143 assessment submissions.
**Outcome distribution:** Distinction 792, Pass 682, Fail 481, Withdrawn 285 →
34.2% at-risk base rate.

### What this means for the reported numbers

The metrics in `README.md` are **real measurements of this pipeline on this
data**, not estimates. They are honest evidence that the code works, the leakage
controls hold, and the model learns the intended signal. They are **not** a claim
about how well the model would score on the real OULAD data — the synthetic
generative process is simpler than real student behaviour, so real-world metrics
should be expected to be lower. Re-run `make train` after dropping in the real
CSVs to get figures that can be quoted.

## Fallback dataset

If OULAD is unavailable, the UCI dataset **"Predict Students' Dropout and
Academic Success"** (dataset 697, CC BY 4.0, 4,424 rows, 36 features) is a
reasonable substitute: it separates enrolment-time information from 1st/2nd
semester performance, giving the same early/late split the checkpoint mechanism
relies on. It would require rewriting `src/data/features.py`, since it is a flat
one-row-per-student table with no event-level timestamps.
